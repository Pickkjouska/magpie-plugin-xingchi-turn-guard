# BF-003：独立重写历史与限额模块

版本 `0.3.2` 将 `history.mjs` 和 `turn-limits.mjs` 替换为针对本插件公开接口和行为契约的独立实现。这些模块没有第三方运行时包依赖，代码只使用 Node.js 自带模块。

最初的插件版本直接改写了另一项目中的两个模块。它们不是通过包管理器安装的运行时依赖，但仍属于 MIT 衍生代码，所以当时必须随分发包保留相应声明。此次由隔离任务中的实现者仅依据包 manifest、README、行为测试及调用方接口重写模块；该实现者没有读取原模块、第三方声明或上游源码。协调审查者此前为核实许可情况读过原实现和来源提交，但没有向实现者提供源码片段，也没有编写新的模块代码。

重写后，发布包不再分发基于该上游实现的代码，因此移除了随包携带的 `THIRD_PARTY_NOTICES.md`。历史版 `0.3.1` 发布档案仍保留其原有声明；它是旧版本的正确快照，不代表 `0.3.2` 仍含该衍生实现。

隔离副本使用新模块运行两套公开回归测试：65 项测试、607 次断言全部通过。新增覆盖包括重复精确打包时恢复图片和文件、不完整 item reference 依赖不被错误归档、乱序缓存反馈不能抬高预算、损坏缓存不会阻断请求，以及文本错误报告的零回复数不会被学为有效上限。两份模块通过 `node --check`。测试只用临时目录和合成凭据，没有向真实模型或原会话发送请求。

安装后也用本地合成网关验证了 v0.3.2 插件：105 个模型条目、约 474 KB 的普通请求被缩至 6 个模型条目、约 44 KB，并以 HTTP 200 完成。同一测试还确认，在 Magpie 0.1.4759 中，Codex 内部 `compaction_trigger` 仍会把原始合成历史发到假上游并得到 HTTP 400；该版本对内部压缩请求绕过普通网关 hook。这是只更新插件包时的宿主限制。

缓存写操作在一个插件宿主进程内串行化。多个进程同时写同一配置目录时仍可能有读改写竞争；缓存只保存已观察到的限额摘要，读取或写入失败会退回配置预算并继续请求。
